# Session bootstrap: the wrapper greetd execs, `mura-session.target`, and the environment contract

**Status:** draft rev 1 (2026-09-24) — written for the D-track rung **D4** against the sway
stand-in session ([implementation-path.md §3c](../docs/architecture/implementation-path.md));
revised at **G3** when the zxr session replaces sway. Normative for `modules/os/session.nix`.
**Design source:** [implementation-path.md §2 (ii) B6/B6a](../docs/architecture/implementation-path.md),
[ADR 0007](../docs/architecture/adr/0007-session-greeter-lock.md) (session body, crash/restart,
boot-locked restart), [session-auth.md §5](session-auth.md) (greetd's exit-then-start ordering),
[first-run-onboarding.md §5.3](../docs/architecture/first-run-onboarding.md) (the passwordless
posture the PAM session step inherits).
**Grounding:** "XDG" here is the Base Directory spec (`$XDG_RUNTIME_DIR`); the systemd
`graphical-session-pre.target` / `graphical-session.target` conventions are freedesktop's and are
used unmodified so upstream portals, PipeWire and D-Bus activation integrate without patches.
**Budget impact** (overview invariant 9): login-time process work; the wrapper sleeps for the
lifetime of the session; nothing on the frame path.

## 1. The problem this spec closes

greetd's session worker `exec`s **one command** as the user after PAM `open_session`. A systemd
*target* is not an executable, a user unit cannot `BindsTo=` the system manager's session scope,
and greetd (multi-user profile) restarts the greeter the moment its session command returns —
so whatever greetd execs must (a) bring the user's systemd manager to the XR session target,
(b) publish the compositor's runtime environment to user services *only after the compositor is
ready*, and (c) **stay alive until the whole session is torn down**, or the next greeter races
the compositor for the DRM device. That executable is the **session wrapper**,
`mura-session-wrapper`. On the appliance profile greetd's `initial_session` execs the same
wrapper; only the return path differs (§6).

## 2. Actors

| Actor | Runs as | Role |
|---|---|---|
| greetd session worker | root → drops to the user | PAM (`greetd` service): `authenticate`, `open_session` (which starts `pam_systemd` → logind session + user manager + `$XDG_RUNTIME_DIR`), then `exec` of the session command |
| `mura-session-wrapper` | the user | the executable greetd execs; owns coupling between the greetd session and the user target; returns only after teardown |
| user `systemd --user` | the user | hosts `mura-session.target` and everything under it |
| `mura-session.target` | user unit | the XR session body: Monado, the compositor, shell services (ADR 0007) |
| `monado.service` (user) | the user | socket-activated OpenXR runtime; the session's *own* Monado instance |
| the compositor | the user | `zxr` (or sway, the stand-in until M1); sd-notify readiness; creates `WAYLAND_DISPLAY` |
| `graphical-session-pre.target` / `graphical-session.target` | user units (upstream) | freedesktop's layering points; Mura adds nothing to them, only orders around them |

## 3. Environment: three classes, three publication moments

| Class | Examples | Set by | Visible to |
|---|---|---|---|
| **Static** | `XR_RUNTIME_JSON`, locale (`LANG`), `XDG_SESSION_TYPE=wayland`, `XDG_CURRENT_DESKTOP=mura`, `MURA_PROFILE` | `environment.d` drop-ins generated by the NixOS module; PAM `pam_env` for the greetd service | the user manager at start, hence every user unit; the wrapper inherits them from greetd's exec |
| **Compositor-created** | `WAYLAND_DISPLAY`, `DISPLAY` (Xwayland, when present), `XDG_SESSION_ID` (already in the environment from PAM) | the compositor, published **only after** it has signalled readiness (`sd_notify(READY=1)` with `WAYLAND_DISPLAY` known) | user services started *after* `graphical-session-pre.target`; D-Bus-activated services via `dbus-update-activation-environment` |
| **Dependent** | nothing set; these are *consumers* | portals, PipeWire/WirePlumber, the settings daemon, notification service, shell services | ordered `After=graphical-session-pre.target`, `PartOf=graphical-session.target` — upstream's own conventions |

Rule: **no compositor-created variable is ever exported before readiness**, and no dependent
service is ordered before `graphical-session-pre.target`. A `WAYLAND_DISPLAY` that names a socket
nobody listens on is the classic race this spec forbids.

## 4. The wrapper, step by step

1. **Entry.** greetd has `exec`ed the wrapper as the user; `$XDG_RUNTIME_DIR`, `$XDG_SESSION_ID`
   and the static environment are set. The wrapper verifies `systemctl --user is-system-running`
   reaches `running` or `degraded` within a bounded wait (the user manager is started by
   `pam_systemd`; on the very first login of a fresh account this may take a moment).
2. **Import static environment** into the user manager where PAM did not already:
   `systemctl --user import-environment XR_RUNTIME_JSON LANG …` (explicit list — never
   `import-environment` without arguments, which drags the whole greetd environment along).
3. **Start the session body**: `systemctl --user start --no-block mura-session.target`. The
   target `Wants=` the compositor unit and `monado.service`'s socket; `PartOf=` nothing (it is the
   root of the tree).
4. **Wait for readiness**: block on the compositor unit becoming `active` **and** on
   `graphical-session.target` becoming active (the compositor unit is what reaches it — §5).
   Bounded (default 30 s, schema-declared); on timeout, go to step 7 with a failure code.
5. **Publish the compositor-created environment**: the compositor itself, in its readiness
   hook, runs `systemctl --user set-environment WAYLAND_DISPLAY=… [DISPLAY=…]` and
   `dbus-update-activation-environment --systemd WAYLAND_DISPLAY [DISPLAY]`, **then** starts
   `graphical-session-pre.target` and `graphical-session.target` (as upstream compositors do:
   sway's `exec systemctl --user start graphical-session.target` idiom; zxr does this natively).
   The wrapper does not publish these — it only waits for them.
6. **Sleep, coupled.** The wrapper stays alive for the session's lifetime: it `systemctl --user
   ... --wait` on `mura-session.target` (or polls a `WaitForJob`) so that it **returns exactly
   when the target has stopped**. It handles `SIGTERM`/`SIGHUP` (greetd or logind tearing the
   session down) by stopping `mura-session.target` and continuing to wait for that stop.
7. **Teardown, in order.** `systemctl --user stop mura-session.target` (stops the compositor and
   Monado; `graphical-session.target` stops through `PartOf=`); wait for the compositor process
   to have released the DRM master and the Monado socket to be gone; only then **return**. Exit
   code: `0` for a normal logout, `1` for a readiness timeout or compositor failure (greetd
   logs it; the greeter restarts either way on the multi-user profile).

The wrapper is a small program (shell is acceptable for D4; Rust when zxr lands) with no
privileges and no D-Bus surface of its own.

## 5. Units and ordering

```
mura-session.target (user)
├── Wants=  mura-compositor.service          # zxr session mode; sway until M1 (STAND-IN)
├── Wants=  monado.socket                     # socket-activated; the session's own instance
└── (graphical-session-pre.target, graphical-session.target: reached BY the compositor, §4.5)
        └── PartOf=graphical-session.target: portals, pipewire/wireplumber, settings daemon,
                                             shell services — upstream ordering, unmodified
```

- `mura-compositor.service`: `Type=notify`, `NotifyAccess=all`, `Restart=on-failure` per
  ADR 0007's crash semantics (a crash restarts **into the locked state** when a credential
  exists — the lock state machine's job, not the wrapper's), `ExecStopPost=` releases nothing
  (DRM master release is implicit in process exit; the wrapper's step 7 *observes* it).
- `monado.service`/`monado.socket`: the upstream `services.monado` user units; the compositor
  connects to the socket, so activation order is implicit. **Two Monado instances never overlap**:
  the greeter's Monado (system-level, owned by greetd's session) has exited before greetd execs
  the wrapper (session-auth §5's exit-then-start), and the session's Monado belongs to the user
  manager and dies with `mura-session.target`.
- Lifetimes are **manager-correct**: nothing in the user manager references the system manager's
  session scope; the *wrapper process* — which lives in that scope — is the only coupling, and
  it is one-directional (scope teardown → SIGTERM → wrapper stops the target).

## 6. Profiles

- **Multi-user:** greetd `default_session` runs the greeter; `start_session` → the greeter exits
  → greetd execs the wrapper as the chosen user. Wrapper return → greetd restarts the greeter
  (`services.greetd.restart = true`, the NixOS default when no `initial_session` is set). Logout
  is therefore: user target stops → wrapper returns → greeter. User switch = logout + login.
- **Appliance / default image:** greetd `initial_session` execs the wrapper as `mura` at boot;
  `services.greetd.restart = false` (NixOS sets this default when `initial_session` exists, so a
  crash does not autologin in a loop — the compositor's own `Restart=` handles crashes inside the
  session). Wrapper return (logout) leaves greetd's `default_session`: on the default image that
  is the same autologin again — an explicit "power off / restart" is the way out, exactly the
  Steam Deck shape.

## 7. Stand-in specifics (D4, removed at M1)

sway as the session body: `mura-compositor.service` runs `sway`; sway's config carries
`exec systemctl --user set-environment WAYLAND_DISPLAY=$WAYLAND_DISPLAY; systemctl --user start
graphical-session-pre.target graphical-session.target` and `exec-always dbus-update-activation-environment
--systemd WAYLAND_DISPLAY` — the standard sway idiom, i.e. the compositor performs §4.5 itself.
sway has no sd-notify; the unit uses `Type=simple` plus a readiness probe on the socket path in
the wrapper for D4 only. The unit file carries `# STAND-IN — replaced at M1 by zxr`.

## 8. Conformance checklist (VM, both fixtures)

1. **No pre-readiness leak:** a user service ordered `After=graphical-session-pre.target` that
   logs its environment never sees a `WAYLAND_DISPLAY` naming an unbound socket.
2. **Wrapper lifetime = session lifetime:** `loginctl` shows one session for the login; the
   wrapper PID is that session's leader and outlives the compositor by exactly the teardown.
3. **Logout without a race:** on the multi-user fixture, logout → greeter appears; the DRM device
   was released before the greeter's compositor opened it (no `EBUSY`/master-acquire failures in
   the journal; `loginctl session-status` shows the old session gone before the new one takes
   the seat).
4. **Compositor crash:** `kill -9` the compositor → `Restart=on-failure` brings it back inside the
   same session; the wrapper does not return; with a credential set, the session comes back
   locked (ADR 0007) — verified in D5 once authd exists.
5. **Readiness timeout:** a compositor that never signals readiness → the wrapper returns `1`
   within the bound; greetd logs; the greeter restarts (multi-user) / the autologin re-runs
   once and the crash-loop counter increments (default image).
6. **Two Monados never overlap:** at no instant do a greeter-owned and a session-owned Monado
   both hold the HMD (or, in the VM, the simulated device).
7. **Environment import is explicit:** the user manager's environment contains the listed static
   variables and nothing else inherited from greetd (`systemctl --user show-environment`).
